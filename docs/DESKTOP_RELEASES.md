# Desktop releases

The browser app remains a standalone local-first site. This document covers only the optional signed desktop release path; publishing it is a Phase 5 responsibility.

## Version contract

Use SemVer without a `v` prefix. Update the same value in `package.json`, `src-tauri/Cargo.toml`, and `src-tauri/tauri.conf.json`, then run:

```powershell
bun run version:check
```

The command fails if any of the three values drift.

## Signed local build

Tauri verifies updates with a public key embedded only in a signed-release build. Development, no-bundle checks, and ordinary local installers intentionally omit that overlay, so an explicit update check reports that updates are unavailable instead of accepting unsigned content.

Generate a key once in a location outside this repository, retain it securely, and never commit it:

```powershell
bunx tauri signer generate -w "$env:USERPROFILE\.tauri\mod-description-workbench-updater.key"
```

Set the private key path or contents and the generated public-key contents only in your current environment. The public key belongs in the build environment too, not in the repository until an owner explicitly approves the permanent update channel configuration.

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = "$env:USERPROFILE\.tauri\mod-description-workbench-updater.key"
$env:TAURI_UPDATER_PUBLIC_KEY = '<public key contents>'
bun run desktop:release
```

`desktop:release` creates a temporary ignored Tauri overlay, enables updater artifacts, uses only `https://github.com/ifBars/mod-description-workbench/releases/latest/download/latest.json`, and removes the overlay after the build. It never prints the key. If either variable is absent, it fails before starting a release build.

## Artifacts and updater manifest

Windows local bundles are written under `src-tauri/target/release/bundle/`: NSIS creates a `-setup.exe` installer and WiX creates an `.msi`. The release overlay additionally creates signed updater artifacts and `.sig` files. Their exact target/architecture names are generated by Tauri and must be checked after a build.

The GitHub release endpoint must publish `latest.json`, the signed platform installer, and its signature. Its static manifest uses a SemVer `version`, optional `notes` and `pub_date`, and a `platforms.windows-x86_64` object with the installer `url` and `signature`. Keep the release notes plain text because the desktop settings surface displays them as text.

## Phase 5 handoff

Before publishing, an owner must protect the private key, confirm the public key and endpoint, build each supported platform, verify signatures, upload the manifest and signed assets, and then test an installed prior version. This repository currently contains no hosted workflow, release upload, or publishing automation.
